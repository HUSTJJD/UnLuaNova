# UnLuaNovaDefaultParamCollector

## 概述

一个 **C\# 版 UHT 插件**（UBT plugin），在编译 UHT 时导出 `DefaultParamCollection.inl`，把
`UFUNCTION` 的默认参数值收集进 `GDefaultParamCollection`，供 UnLuaNova 在 Lua 侧省略实参时回填。

这是 UnLuaNova 里唯一生效的收集器实现。本仓库基线为 **UE 5.8.3**，而 C++ 版 UHT 自 **UE 5.2 起已被
移除**（`Engine/Source/Programs/UnrealHeaderTool` 与 `IScriptGeneratorPluginInterface.h` 都不再存在），
因此随上游一起带来的 C++ 版 `UnLuaNovaDefaultParamCollector`（Type `Program` 的模块）已删除。


## 引擎如何发现它

不需要在 `.uplugin` 的 `Modules` 里声明。UBT 会扫描插件 `Source` 目录下的
`*.ubtplugin.csproj` 并自动构建，UHT 再加载产出的程序集。

产物输出到：

```
<ProjectRoot>/Binaries/DotNET/UnrealBuildTool/Plugins/UnLuaNovaDefaultParamCollector/
```

`UnLuaNova.uplugin` 里的 `CanBeUsedWithUnrealHeaderTool: true` 仍需保留 —— 它是插件能被 UHT
加载的前提。


## 实现要点

见 `UnLuaNovaDefaultParamCollector.cs`：

+ 入口是 `[UhtExporter]` 标注的静态方法，注册名为 `UnLuaNova`、`ModuleName` 为 `UnLuaNova`

+ 只导出 `EngineRuntime` / `GameRuntime` 两类模块；`UhtModuleType` 与输出目录以注释形式写进
  `.inl`，形如
  `// ModuleName CoreUObject Type EngineRuntime(1)  ModuleGeneratedIncludeDirectory ...`

+ 文件头有一行 `// Generated By C# UbtPlugin`。排查时看 `.inl` 开头有没有这行，就能判断
  UHT 是否真的走到了这个插件

+ `Finish()` 里做了幂等写入：内容没变化就不提交，避免每次编译都触发下游重编


## 与已删除的 C++ 版的差异

导出内容大体相同，差异只在：

+ 本版在文件头增加了 `// Generated By C# UbtPlugin` 注释

+ 模块注释输出 `ModuleType` 的枚举名（`EngineRuntime(1)`），旧版只输出数字（`Type 1`）

+ 部分类型的导出顺序不同（C\# 与 C\+\+ 遍历引擎类型的顺序不同），但导出的类型和函数集合一致


## 注意事项

`UnLuaNovaTestSuite` 同样标记了 `CanBeUsedWithUnrealHeaderTool: true`，但它没有提供 C\# 版本，
所以在 UE 5.1 上仍会打印
`DEPRECATED: C++ UHT being used because 'UnLuaNovaTestSuite' does not have a C# version`，
并导致引擎回退到 C++ 版 UHT。正式工程不需要带测试套件插件；如果发现本插件没生效
（`.inl` 开头没有那行注释），先检查工程是不是多带了它。
